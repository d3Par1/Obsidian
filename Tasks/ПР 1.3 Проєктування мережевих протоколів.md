### 1. Проєкт користувацького протоколу прикладного рівня
Оформити **за формою табл. 1** (нижче). Проєкт повинен містити:
- [ ] **Короткий опис** протоколу (назва, що це за протокол)
- [ ] **Призначення**
- [ ] **Архітектура** (клієнт–сервер / брокер–клієнт / P2P — узгодити з ПР 1.1)
- [ ] **Протокол транспортного рівня** (TCP / UDP, порт — узгодити з ПР 1.2 п. 6)
- [ ] **Формат повідомлень** (заголовок, службові поля, дані — розвинути формат із ПР 1.2 п. 5)
- [ ] **Основні команди / методи** (команди клієнта і відповіді сервера, з коротким описом кожної)
- [ ] **Опис обробки помилок** (коди / повідомлення про помилки, тайм-аути, повтори)
- [ ] У формі табл. 1 є ще рядки **Надійність** та **Приклад використання** — заповнити й їх, щоб таблиця відповідала формі

### 2. Опис усіх протоколів проєкту
- [ ] Описати **всі протоколи**, які будуть використовуватись під час розробки ПЗ за варіантом

### 3. Граф переходів станів користувацького протоколу
За прикладами рис. 1–5 методички (ARQ, HTTP-клієнт, SMTP, MQTT, надійна передача — відправник).
- [ ] Граф **окремо для клієнта**
- [ ] Граф **окремо для сервера**
- [ ] Вершини — **стани** протоколу (напр. «очікування з'єднання», «з'єднання встановлене», «передача даних», «завершення сеансу»)
- [ ] Ребра — **переходи**, підписані подією, що їх викликає (отримання повідомлення, тайм-аут, помилка), і дією у відповідь
- [ ] Показати початковий і кінцевий стани, гілки помилок / тайм-аутів / повторів
- [ ] Команди на ребрах мають збігатися з командами з таблиці п. 1 і з діаграмою послідовності з ПР 1.2

## Теорія для звіту (коротко)

- Розробка протоколу має **три рівні специфікацій**:
  - **специфікація сервісу** — зовнішня поведінка, взаємодії на інтерфейсі сервісу, які бачить користувач (без «як»);
  - **специфікація протоколу** — які взаємодії мають відбуватися для надання сервісу; абстрактна реалізація специфікації сервісу;
  - **специфікація реалізації** — уточнення під обмеження конкретної цільової системи.
- Опис протоколу має бути **незалежним від реалізації** (ОС, платформи); відкриті рішення виносять у **параметри протоколу**.
- Протоколи відкритих мереж публікуються як стандарти (RFC; IETF, ITU-T).
- **Автомат станів (state machine)** — модель станів, у яких може перебувати протокол; кожен стан визначає дозволені дії та відповіді на події.
- **Граф переходів станів (state transition graph)** — вершини = стани, ребра = переходи, викликані подіями (отримання повідомлення, тайм-аут, помилка).
