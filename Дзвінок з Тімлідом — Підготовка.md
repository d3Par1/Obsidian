# 📚 РОЗДІЛ 2 — БАЗА ПРОГРАМУВАННЯ (refresher з нуля)

> Те, що ти знаєш, але міг забути формулювання. Тімлід інколи перевіряє «чи розумієш основи», а не лише фреймворки.

### Q: Що таке змінна і тип даних?
**Змінна** — іменована комірка пам'яті, що зберігає значення. **Тип** визначає, що це за дані і скільки місця займають: `int` (ціле), `float`/`double` (дробове), `char` (символ), `bool` (так/ні).

### Q: Що таке функція? Чим відрізняється від процедури і методу?
Це класичне базове питання — чітке формулювання:
- **Функція (function)** — іменований блок коду, який виконує задачу і **повертає значення**. `int add(int a, int b) { return a+b; }`
- **Процедура (procedure)** — те саме, але **нічого не повертає** (у C/C++ це функція з типом `void`). Термін «процедура» — радше з Pascal; у C/C++ усе називають функціями.
- **Метод (method)** — це **функція, що належить класу/об'єкту** (в ООП). Викликається через об'єкт: `drone.takeOff()`.

> Просте формулювання для дзвінка: *«Функція повертає значення, процедура (void-функція) — ні, а метод — це функція всередині класу.»*

### Q: Параметр vs аргумент?
- **Параметр** — змінна в оголошенні функції (`int a` у `add(int a, int b)`).
- **Аргумент** — конкретне значення, яке передаєш при виклику (`add(3, 5)` → аргументи 3 і 5).

### Q: Передача за значенням vs за посиланням?
- **За значенням (by value)** — функція отримує **копію**. Зміни всередині не впливають на оригінал.
- **За посиланням/вказівником (by reference/pointer)** — функція отримує **доступ до оригіналу**, може його змінити.
```c
void inc_copy(int x)  { x++; }      // не змінить оригінал
void inc_ref(int* x)  { (*x)++; }   // змінить оригінал
```
> Деталі вказівників і reference у C++ → [[Interview Prep Master]] Q1.

### Q: Компільована vs інтерпретована мова (чому C++ і Python разом у вакансії)?
- **Компільована (C/C++)** — код заздалегідь перетворюється у машинний (компілятором) у виконуваний файл. **Швидко**, близько до заліза → для прошивок, керування моторами в реальному часі.
- **Інтерпретована (Python)** — код виконується «на льоту» інтерпретатором. **Повільніше, але гнучко і швидко писати** → для скриптів, обробки даних, тестів, ROS2-нодів.
> Тому в дронах: **C++ — на польотному контролері**, **Python — на companion-комп'ютері / для аналізу логів і автоматизації**.

### Q: Що відбувається при компіляції C/C++?
Три кроки:
1. **Препроцесор** — обробляє `#include`, `#define` (текстова підстановка).
2. **Компіляція** — кожен `.c`/`.cpp` → об'єктний файл (`.o`) машинного коду.
3. **Лінкування (linking)** — об'єктні файли + бібліотеки склеюються в один виконуваний файл.

### Q: Синхронний vs асинхронний код?
- **Синхронний** — команди виконуються по черзі, кожна чекає попередню.
- **Асинхронний** — довга операція (мережа, файл) запускається, а програма не блокується і робить інше, поки чекає результат. У Python — `async/await`.

# 🔧 РОЗДІЛ 3 — C / C++ БАЗА

### Q: Чим C відрізняється від C++?
- **C** — процедурна мова, низькорівнева, без класів. Ядро embedded, прошивки.
- **C++** — надбудова над C: додає **ООП (класи)**, шаблони (templates), RAII, STL. ArduPilot/PX4 написані на C++.

### Q: Що таке вказівник (pointer) — простими словами?
Змінна, що зберігає **адресу** іншої змінної в пам'яті (а не саме значення). Дозволяє читати/міняти дані за цією адресою. Критично для embedded — регістри заліза доступні саме через адреси.
> Повна відповідь + різниця з reference → [[Interview Prep Master]] Q1.

### Q: Стек (stack) vs купа (heap) — коротко?
- **Stack** — автоматична пам'ять для локальних змінних; швидка, маленька, звільняється сама при виході з функції.
- **Heap** — динамічна пам'ять (`malloc`/`new`); велика, але програміст звільняє сам, ризик витоків.
> В **embedded heap часто уникають** (фрагментація, недетермінований час). Деталі → [[Interview Prep Master]] Q2, Q4.

### Q: Що таке клас і об'єкт?
- **Клас** — шаблон/креслення (які дані + які методи). Напр. клас `Motor`.
- **Об'єкт** — конкретний екземпляр класу. `Motor leftMotor;`

### Q: Три кити ООП?
1. **Інкапсуляція** — ховаємо внутрішні дані, доступ через методи (`private`/`public`).
2. **Наслідування** — новий клас успадковує поля/методи базового (`QuadDrone : Drone`).
3. **Поліморфізм** — один інтерфейс, різна поведінка (віртуальні методи: `drone.fly()` працює по-різному для різних типів).
> У тебе є сильна база з курсу ООА — патерни і SOLID: [[OOA/SOLID Принципи]], [[OOA/README]]. Можеш на це послатися.

### Q: const, static, volatile — навіщо (одним рядком кожне)?
- **const** — значення не можна змінювати після ініціалізації.
- **static** — у функції: зберігає значення між викликами; у файлі: обмежує видимість цим файлом.
- **volatile** — «не оптимізуй, значення може змінитись ззовні» — для регістрів і змінних з переривань.
> Розгорнуто → [[Interview Prep Master]] Q3.

# 🐍 РОЗДІЛ 4 — PYTHON БАЗА (роль = C++/Python)

### Q: Чим Python відрізняється від C++?
Інтерпретована, з динамічною типізацією (тип змінної не оголошуєш), автоматичне керування пам'яттю (garbage collector), дуже швидко писати. Ціна — повільніше і більше пам'яті.

### Q: Список vs кортеж vs словник?
- **list** `[1,2,3]` — впорядкований, **змінний**.
- **tuple** `(1,2,3)` — впорядкований, **незмінний**.
- **dict** `{"key": "value"}` — пари ключ-значення, швидкий пошук за ключем.

### Q: Навіщо Python у дронах?
- Скрипти автоматизації, обробка/візуалізація логів польоту.
- **pymavlink** — читати/слати MAVLink-повідомлення з ПК.
- **ROS2** ноди на Python (rclpy).
- Тести, прототипи алгоритмів перед портуванням у C++.

### Q: Що таке async/await у Python (коротко)?
Спосіб писати асинхронний код: `await` призупиняє корутину поки чекає результат (мережа/IO), не блокуючи весь процес. У тебе є практичний приклад — Telegram-боти на `asyncio`.

# ⚙️ РОЗДІЛ 5 — EMBEDDED / МІКРОКОНТРОЛЕРИ (база)

### Q: Що таке мікроконтролер? Чим відрізняється від процесора/комп'ютера?
**Мікроконтролер (MCU)** — маленький комп'ютер на одному чіпі: CPU + пам'ять (Flash + RAM) + периферія (GPIO, таймери, UART…). На відміну від процесора в ПК — працює **без ОС** (bare-metal) або з RTOS, малопотужний, але дешевий і енергоощадний. Приклади: **STM32, ESP32, RP2040 (Pico)**.

### Q: Що таке GPIO і «пін»?
**GPIO (General Purpose Input/Output)** — універсальні ніжки (піни) мікроконтролера, які можна налаштувати як **вхід** (читати кнопку, сигнал) або **вихід** (запалити LED, керувати реле).
> Режими (pull-up/pull-down, push-pull/open-drain) → [[Interview Prep Master]] Q12.

### Q: UART, I²C, SPI — простими словами (одне речення кожне).
- **UART** — два дроти (TX/RX), проста зв'язок «точка-точка» (GPS, консоль).
- **I²C** — двопровідна шина (SDA/SCL), багато пристроїв з адресами на одних дротах (сенсори).
- **SPI** — швидка шина (4 дроти), для дисплеїв, SD-карт, швидких сенсорів.
> Порівняльна таблиця → [[Interview Prep Master]] Q11.

### Q: Що таке переривання (interrupt)?
Механізм, коли залізо **саме сигналить** процесору, що сталася подія (натиснули кнопку, прийшов байт по UART), і CPU миттєво відволікається на обробник (ISR), замість постійно опитувати (polling).
> Правила ISR + polling vs interrupts → [[Interview Prep Master]] Q9, Q10.

### Q: Що таке прошивка (firmware) і flashing?
**Firmware** — програма, зашита в Flash-пам'ять мікроконтролера, що керує залізом. **Flashing (прошивання)** — процес заливки цієї програми в MCU (через USB, ST-Link, UART-bootloader).

### Q: Сенсори дрона — що міряє кожен?
- **Accelerometer** — лінійне прискорення (де «низ»/гравітація).
- **Gyroscope** — кутову швидкість обертання.
- **Magnetometer** — напрямок (компас).
- **Barometer** — тиск → висоту.
- **GPS** — позицію (широта/довгота/висота).
- **IMU** = accelerometer + gyroscope (+ часто magnetometer) в одному чіпі.
> Sensor fusion / Kalman → [[Interview Prep Master]] Q20, Q22.

# 🚁 РОЗДІЛ 6 — ДРОНИ / UAV (серце цієї ролі)

### Q: З чого складається типовий дрон (квадрокоптер)?
- **Рама (frame)** — каркас.
- **Мотори (4 шт)** + **пропелери**.
- **ESC (Electronic Speed Controller)** — регулює оберти кожного мотора.
- **Flight Controller (FC)** — «мозок»: читає сенсори, рахує корекції, керує ESC.
- **IMU** — на платі FC.
- **RC-приймач** — приймає команди з пульта.
- **Батарея (LiPo)** + розподільна плата живлення.
- (Опційно) **GPS, камера, телеметрія, companion-комп'ютер**.

### Q: Що таке польотний контролер (flight controller)?
Плата з мікроконтролером, що виконує **цикл стабілізації**: зчитує IMU → порівнює з бажаною орієнтацією → через **PID** рахує корекції → задає оберти моторам через ESC. Робить це сотні-тисячі разів на секунду.

### Q: Betaflight vs ArduPilot vs PX4 — простими словами?
- **Betaflight** — прошивка для **FPV/acro** дронів: легка, швидка реакція, ручне пілотування. Менше автономії.
- **ArduPilot** — потужна автономія (waypoints, місії, RTL), велика спільнота, ліцензія GPLv3. Hobby + комерція.
- **PX4** — модульна, RTOS (NuttX), ліцензія BSD (commercial-friendly), сильна для R&D і досліджень.
> Усі підтримують **MAVLink**. Порівняння PX4/ArduPilot → [[Interview Prep Master]] Q18.

### Q: Що таке MAVLink?
Компактний **бінарний протокол** для зв'язку дрон ↔ наземна станція (QGroundControl/Mission Planner) ↔ компоненти. Передає HEARTBEAT, ATTITUDE, GPS, команди, місії. Працює через UART/UDP/USB.
> Структура пакета і парсер → [[Interview Prep Master]] Q17.

### Q: Що таке PID-контролер (простими словами)?
Алгоритм керування зі **зворотним зв'язком**, що тримає дрон стабільним:
- **P** — реагує на поточну помилку (відхилення).
- **I** — компенсує постійний знос (вітер).
- **D** — гасить коливання (реакція на швидкість зміни).
> Аналогія з кермуванням авто + як тюнять → [[Interview Prep Master]] Q19.

### Q: Що таке польотні випробування (flight tests) і яка тут роль інженера?
Перевірка дрона/прошивки в реальному польоті: bench-тести моторів → hover-тест → польотні місії. Інженер: готує конфіг, знімає **телеметрію і логи**, аналізує (вібрації, PID, відмови), вносить правки. Це ітеративний цикл «зміна → тест → лог → правка».
> Будь готовий сказати: *готовий бути «руками» на полігоні, знімати логи, вчитися читати їх.*

### Q: Навіщо 3D-моделювання в дронах?
Проєктування і друк **корпусів, кріплень, адаптерів, антенних маунтів, захисту електроніки**. Інструменти: **Fusion 360 / FreeCAD / Blender** → друк на 3D-принтері. У тебе вже є досвід **Blender** — це твоя перевага, згадай її.

# 🤖 РОЗДІЛ 7 — ROS2 (якщо суміжна роль / спитають)

### Q: Що таке ROS2 і навіщо в дронах?
**ROS2 (Robot Operating System 2)** — не ОС, а **middleware** (набір бібліотек) для робототехніки: запускає багато процесів-**нодів**, які обмінюються повідомленнями. У дронах — на **companion-комп'ютері** (Raspberry Pi/Jetson) для computer vision, SLAM, автономії.

### Q: Базові поняття ROS2?
- **Node** — окремий процес, що щось робить (напр. читає камеру).
- **Topic** — канал повідомлень (`/camera/image`).
- **Publisher / Subscriber** — хто пише в topic / хто читає.
> Архітектура PX4↔ROS2 → [[Interview Prep Master]] Q25.

# 🛠️ РОЗДІЛ 8 — ІНСТРУМЕНТИ / ПРОЦЕС

### Q: Git — базові команди і навіщо?
Система контролю версій. `clone` (скопіювати repo), `add`/`commit` (зберегти зміну), `push`/`pull` (синхр. з віддаленим), `branch` (гілка для фічі), `merge`/PR (злити). Дозволяє командну роботу й історію змін.

### Q: Як дебажити embedded (без звичного дебагера)?
- **Serial print** (`printf` через UART) — найпростіше, дивишся вивід у терміналі.
- **LED-індикація** — блимаєш світлодіодом у певних точках коду.
- **Logic analyzer / осцилограф** — дивишся реальні сигнали на пінах.
- **Дебагер по JTAG/SWD** (ST-Link) — breakpoint'и, перегляд регістрів.

### Q: Linux база, яку очікують?
Навігація (`cd`, `ls`), права (`chmod`), процеси (`ps`, `kill`), сервіси (`systemctl`), логи (`journalctl`), Bash-скрипти.
> Деталі (chmod 755, systemd, signals) → [[Interview Prep Master]] Q29–Q31.

### Як казати «не знаю» правильно
❌ «Не знаю» + мовчання.
✅ Чесно + напрямок думки + готовність вчитися:
> «З цим конкретно ще не працював. Але якщо міркувати — це, ймовірно, [твоя логіка]. Підкажіть, як це у вас — мені цікаво розібратися.»

Це **сильніше**, ніж вдавати знання: тімлід цінує чесність + інженерне мислення.
